# FlowScope

FlowScope 是一个基于 TqSdk 的期货行情监控页面（主图周期 10s / 30s 可选），提供主动买卖量、Volume Suite、Delta、CVD 与 LSMA×CRVOL 等指标。

## 启动

1. 创建 Python 3.12 虚拟环境并安装依赖：

   ```powershell
   py -3.12 -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

2. 在项目根目录复制 `.env.example` 为 `.env`，填写 TqSdk 账号：

   ```powershell
   Copy-Item .env.example .env
   ```

   服务启动时会自动读取 `.env`；也可以继续使用系统环境变量覆盖同名配置。

3. 启动服务：

   ```powershell
   .\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000
   ```

   也可以运行 `run.bat`（等同上面的命令，盘中用）。开发时用 `run.bat dev`：改后端 `*.py` 自动重启 uvicorn，但**每次重载都是整个进程重启**，行情要断开重连、内存里的 K 线与 tick 窗口要重建，页面会空几秒，盘中不要用。`docs/`、`tests/`、`.venv` 不在监视范围；`static/` 下的前端文件每次请求都从磁盘读，改完刷新页面即可，两种模式都不必重启。

浏览器访问 `http://127.0.0.1:8000/`。图表库已随项目放在 `static/vendor/`，可离线打开；若本地文件不可用，页面会回退到 CDN。行情线程断线时会自动重连，状态可通过 `/api/status` 查看。

## 数据与口径

- 左侧「自选」面板是行情软件式的自选列表：在合约选择器里用 ☆ 加自选（主连和具体月份都可以收藏，见下一条），面板按添加顺序列出名称、合约代码、最新价与涨跌幅（**红涨绿跌**，涨跌幅相对昨结算，取不到昨结算时退回昨收），第三行再给一行更淡的**当日成交量与成交额**（`量 55.6万 · 额 231.2亿`，取不到就不占位置）用来判断流动性；点一行即切换、悬停点 × 即移出。自选存在服务端 `data/favorites.json`（临时文件 + `os.replace` 原子替换，最多 40 个），**所有浏览器共用一份**；手工编辑该文件后不必重启，按 mtime 自动重读。面板折叠状态只记在浏览器 `localStorage` 里。报价走 `GET /api/watch`：只 `get_quote` 读报价对象，**不订阅 K 线与 tick**，也不额外 `wait_update`（采集循环每秒本来就在 `wait_update`），所以 3 秒一次的轮询不会挤占采集线程；面板折叠或页面切到后台时停止轮询。行情源不可用时面板照样列出代码、可点击切换和增删，只提示「行情未就绪」。
- **持仓量统一按单边口径显示。** TqSdk 静态合约查询的 `pre_open_interest` 在**上期所 / 能源中心 / 郑商所 / 大商所是双边计量**，其余交易所（中金所、广期所）是单边；而报价对象的 `open_interest` 一律单边。若不归一，同一合约同一时刻在菜单里会显示成自选面板的 2 倍（实测这四家的静态值 ÷ 报价值精确等于 2.000，中金所 / 广期所等于 1.000）。所以 `catalog.single_side_open_interest()` 对这四家除以 2，菜单的「昨仓」与自选面板的实时持仓量从此可直接比大小。归一只是乘一个常数，**不影响任何排序结果**（同一品种缩放系数相同）。新增交易所不在双边列表里时保持原值 —— 宁可少除，也不要凭猜测把数字改错。
- 默认合约是 `KQ.m@SHFE.fu`，可在页面中切换；服务最多保留 32 个订阅（按「合约＋主周期」计数）。
- **常驻采集**：买卖量历史只能靠持续采集积累（TqSdk 不提供历史 tick），所以默认合约与全部自选的**每个主周期**（10s、30s）都常驻订阅，不需要开着页面，也不参与闲置回收，关掉浏览器照常计算、落盘。常驻最多占一半订阅名额（16 个，即默认合约加 7 个自选），剩下的留给页面临时打开的合约；超出的自选只在页面打开时采集，在 `/api/status` 的 `collectSkipped` 列出。收藏、取消收藏、读自选列表时同步常驻集合，手工改过 `data/favorites.json` 也会在面板下一次读列表时跟上。取消收藏后，该合约回到普通的闲置回收规则，**闲置期从取消时起算**（满 600 秒才回收），不会立刻断开。
- 工具栏「选择合约」是**自研的二级级联菜单**（`static/contract-picker.js` + 纯逻辑 `static/picker-core.js`，不用原生 `<select>`）：一级列全部品种，交易所作为吸顶分组标题，行内是「中文名 · 主力月份 + 昨日持仓量」，按主力合约昨日持仓量降序；二级列该品种的月份，**第一项恒为「★ 主力」**（= 主连 `KQ.m@交易所.品种`），其余是 `SHFE.fu2611` 这类可交易合约，同样按昨仓降序。交互：搜索框输入即过滤一级（匹配中文名/品种代码/主连代码/主力合约/交易所代码），鼠标悬停品种即预取并显示月份（120ms 防抖，扫过列表不会连发请求），点月份行切换，双击品种 = 直接切主力；**每行右侧的 ☆ 直接加/移出自选**（品种行收藏的是该品种主力，与二级第一项同一个合约），点它不切换合约、不关菜单，可以连着收藏几个，提交中星号变淡、失败会自动回到原状态并在工具栏提示原因；菜单里的 ☆ 与左侧自选面板共用同一份服务端自选，任何一处改动都会就地重画（不重排列表，滚动位置不丢）。键盘 `↑↓` 移动、`→`/`←` 换列、`Enter` 确认（一级回车 = 主力）、`Home`/`End` 首尾、`Esc`/`Tab` 关闭，点击浮层外也会收起。触发器上直接显示当前「品种 · 主力月份」。
- 目录数据仍来自 `GET /api/symbols`（服务端缓存：品种 5 分钟、月份 1 分钟）；前端再加一层 `localStorage` + 内存缓存，菜单基本秒开，悬停预取让二级通常已经就绪。行情线程没连上时服务端回退到内置常用品种表，工具栏提示「目录: 离线常用品种」；月份取不到时二级只剩「★ 主力」可选并说明原因。**切换合约只有选择器这一个入口**（选中的合约写回 URL 的 `?symbol=`，与手填 URL 走同一条切换/重连路径）；顶栏那个合约名是**只读展示位**，由 `GET /api/symbol` 解析：主连会解析成当前标的月份合约的中文名（`KQ.m@SHFE.fu` → 「燃油2611」，随换月变化），鼠标悬停显示原始代码，行情源不可用时回退成代码本身。原来的手填输入框 + 「切换」按钮已移除 —— 需要临时打开目录之外的合约（如 `KQ.i@SHFE.fu`）时直接改 URL。工具栏的「☆ 收藏」按钮同样已移除：**收藏入口只有选择器每行的 ☆**，所以目录之外的合约收藏不了（需要的话手工编辑 `data/favorites.json`，服务端按 mtime 自动重读）。目录只做静态合约查询、**不订阅行情**：为排序去订阅上百路月份报价既慢又会把订阅池越撑越大，而「谁是主力」另有权威来源（主连的标的合约），不靠持仓量排序猜。
- 工具栏「周期」在 **10s / 30s** 之间切换主图周期，K 线、成交量、足迹图、CVD 全部按所选周期重算。周期是**订阅级维度**：同一合约的不同周期是各自独立的 Feed（`/api/status` 里显示为 `合约@10s`、`合约@30s`），各自订阅 K 线、各自聚合与落盘，互不串消息；tick 口径共用同一路 tick 流。
- **指标长度按"根数"固定**，与 TradingView 切周期行为一致：`smalen=300`、`rellen=20`、`zlen=50` 都是根数，不随时间跨度换算。所以 10s 下 300 根均线只覆盖 50 分钟（30s 下是 2.5 小时），指标会比 30s 更灵敏。K 线根数窗口同样固定：服务端保留 2000 根、前端显示 800 根，因此 10s 视图覆盖约 2.2 小时、30s 视图约 6.7 小时。
- 拆分粒度随主周期收敛，必须**整除**主周期且不比它更粗：30s 下为 1/5/10/15/30，10s 下只剩 1/5/10（15、30 在前端被禁用）。当前选择若变得非法会自动回落到该周期下最粗的合法粒度。
- 工具栏「CVD口径」提供两种选择，也同步影响 Delta 与买卖量。默认「TqSdk tick口径」（`ltf=0`），使用 tick 快照盘口**估算**主动方向，此时禁用拆分粒度。快照区间成交量不能还原区间内逐笔成交的方向和价格。
- tick 口径的主动方向按 **Lee-Ready 三级判定**：① 报价规则——成交价 ≥ **前一** tick 的卖一记买，≤ 前一 tick 的买一记卖（必须用前一档：快照盘口是成交后的最新挂单，一笔吃掉卖一后买一会随即上移，拿自己的盘口比会把主动买判成主动卖）；② 中点规则——价格落在价差内部时，高于中点记买、低于中点记卖；③ 逐笔规则——价格高于上一成交价记买、低于记卖，同价成交（zero tick）沿用已确定方向。三条都用不上才记**未知**，单独成桶，不猜也不沿用。判向状态只在有成交的快照上推进，无成交的报价更新不加量也不改写沿用方向；跨交易日（累计量清零）或快照间隔超过 60 秒的断档会重置状态。完整 Lee-Ready 下未知量天然很少，它兜住的是"毫无判据"的残差。
- **前端恒读新算法 Lee-Ready**：工具栏原有的「判向算法」开关已移除，不再提供切到旧算法的入口。旧算法（原快照自身盘口口径）结果仍与主列并列落盘，字段是 `buyLegacy/sellLegacy`（另见 `deltaLegacy`），仅供离线对照（`evaluate_indicators.py`）与十字光标提示；旧算法与当根 K 线方向一致率只有约 33%（系统性反向，见 `docs/indicator-accuracy-2026-09-16-addendum.md`），保留开关只会带来误判风险。整段窗口的成交总量在三个桶之间守恒：`buy + sell + unknown == observed`。CVD 恒按新算法累计，与对照列无关。
- 「TV K线口径」直接订阅 TqSdk 小周期 K 线，按 `close > open` 把该根成交量计为买量，`close < open` 计为卖量，十字线不计入买卖量，再汇总到 30 秒。拆分粒度支持 1s、5s、10s、15s、30s，默认 10s，切回时记住本次页面使用的粒度。该口径没有 tick 判向，未知恒为 0，对照列与主列同值。两种口径的数据源均为 TqSdk；TV 表示 Pine 的计算方法，数据源与累计起点仍可能导致结果与 TradingView 不同（实测差异量与根因见下文《与 TradingView 的差异》）。
- 工具栏「阈值」决定成交量与 Delta 的等级分档口径（RELATIVE / SMA / Z-SCORE），默认 **Z-SCORE**（窗口 `zlen=50`，三种口径的档位倍数都取 `cfg.mult`）。CVD/Delta 的 RELATIVE 颜色阈值对齐 Pine：正负 Delta 分别除以各自的 20 根均值，严格大于 `[1.5, 2.5, 3.5] × 1.5` 才进入相应等级。
- 工具栏「视图」可切换到足迹图（固定 ltf=0 口径）。按原始成交价聚合，价格步长来自合约 `price_tick`；元数据未知时不推断步长，也不显示对角不平衡。稀疏成交档位只与相隔一个实际 tick 的价位比较。每档为 `[价格, 买量, 卖量, 未知量]`，判不出方向的那部分量以中性紫整条压在格子底部，只参与档位总量、不计入左卖右买。
- 工具栏「叠加」把 **FlowWave 的回归通道**画到主图（默认**关**，副图 FlowWave 原样保留、不受影响）：中线是**收盘价的线性回归**（21 根，与 `wave` 用的是同一个 `linreg` 核，只把输入从振荡值换成价格），上下轨是中线 ± **k 倍回归残差标准差**（同一 21 根窗口，总体标准差除以 n；k 由「带宽」选，默认 2σ）。之所以不能把 `wave`/`wt2` 直接画上去：它们是 0~100 的振荡值（实测还会溢出到 −14~108），没有价格量纲，画到价格轴上必须先选一种映射。这里选「轨道由价格自证」——**轨道本身是真实价格**，可以当动态支撑/压力；FlowWave 的信息以两种方式叠上去：`wt2 > 80` 的段染红、`< 20` 的段染绿（带底淡填 + 对应轨线加深，中性段是灰），以及**每轮首次越界**那一根在对应轨道上打点（连续越界不重复打点）。实测 800 根 fu 30s：`linreg(21) ± 2σ` 的收盘包含率 **91.0%**，与布林带 `(20, 2σ)` 的 85.8% 同量级；首次越界事件只有 22 次上穿 80 / 15 次下穿 20（合计约 4.6% 的 bar），打点密度不会糊图。复算脚本 `docs/flowwave_band_probe.py`。注意两点：① 残差标准差要凑满 21 根残差，所以带比中线晚 20 根出现（共 41 根预热），窗口左边缘是空的；② 末根未收盘时回归线与带宽会随新 tick 抖动，与副图 `wave` 的抖动同源。切到足迹图视图时叠加自动隐藏（足迹格子已经很密），切回 K 线按开关恢复；开关只影响主图，副图中的 CRVOL 斜率与 RVOL 脉冲仍是唯一能看它们的地方。
- 工具栏「带宽」是叠加带的倍数 **k**（上下轨 = 中线 ± k 倍回归残差标准差），三档 **1.5σ / 2σ（默认）/ 2.5σ**，只在「叠加」打开时可调（在足迹图下不置灰——带只是被临时藏起来，切回 K 线仍按所选宽度画）。实测 800 根 fu 30s 的收盘包含率：**1.5σ 81.1% / 2σ 91.0% / 2.5σ 96.6%**，所以「觉得带太窄」就切 2.5σ——越窄触碰信号越多、假信号也越多，越宽则越少被穿。非法值（目录之外的倍数）会回落到默认 2σ 并把下拉框显示纠正回来，不按垃圾值画带；切宽度只重算带本身（中线、wt2 状态、越界点都不受影响），不触发整体 `derive()`。
- **tick 快照按 `(start, end]` 归属 bar**：恰好落在边界上的快照记进前一根，与 TqSdk K 线的切分一致（`indicator.tick_bar_start`）。上期所/能源中心的快照都在 500ms 整点，每根 bar 都有一条落在边界上；早先按 `[start, end)` 分桶会把它记进后一根，实时数据里只有约 4.5% 的 bar 成交量与 K 线相等。2026-09-28 用 `docs/verify_tick_bar_boundary.py` 对七个交易所主连核对，`(start, end]` 下成交量与收盘价 100% 相等。**这一天之前落盘的 v3 行按旧口径分桶，没有改写、也没有换文件**：新旧口径只是把边界上一个快照在相邻两根之间挪了位置，连续区间的总量不变，接缝处的 CVD 最多差一个快照的量。
- 每根 bar 带 `coverage`：`complete` 表示 tick 有前置快照或小周期 K 线根数齐全，且区间量与主周期成交量一致；`partial` 为部分覆盖或数据尚未对齐；`missing` 为无数据；`legacy` 为旧格式历史回填。“完整”指覆盖范围，方向和分价成交量仍是估算。
- tick 历史写入 `data/{symbol}_{tf}s_ltf0_v3.csv`，K 线口径写入 `data/{symbol}_{tf}s_kline_ltf{ltf}_v3.csv`（`tf` 为主周期秒数），各周期、各口径、各粒度独立；K 线口径不读取旧版本由 tick 拼接小周期的缓存。只保存已完成、覆盖完整的 bar。窗口滚动后的部分数据不会覆盖已确认的完整记录；同一时间的修订追加到文件，重启读取最后一条。**`tf=30` 时文件名与历史完全一致**（`{symbol}_30s_...`），既有 30s 历史无缝沿用；10s 是全新文件，不与 30s 混流。
- **v3 是换算法后必须启用的新文件**：`v2` 里的 `buy/sell` 是旧算法结果，若继续混读会被当成新算法，还会让 CVD 在接缝处跳变。因此 `v2` 与更早的 `data/{symbol}_30s.csv` 都退为**只读回填来源**，显示时标记 `legacy`，永远不会被改写；`v3` 从启用时刻起建立自己的 CVD 基准。
- 已完成但未通过成交量核对的快照估算量**与核对通过的量写在同一个文件里**，用行内的 `source` 列区分：`complete`（已核对）/ `partial`（估算）/ `legacy`（旧格式回填）。同一时间戳后写的行优先，所以一根 bar 从 `partial` 升级为 `complete` 只是再追加一行，不需要跨文件去重。文件只追加，因此重启和周期刷新都是**增量读**：只解析上次偏移量之后的新字节，无变化时只是一次 `stat`。旧的 `*_v3_estimated.csv` 仍会被读入（只读，优先级低于主文件），但不再写入，也不会被删除 —— 迁移是纯增量的，没有转换脚本；既有无 `source` 列的 `*_v3.csv` 全部按 `complete` 读。这类旧文件的表头只有 6 列，而当前每行多写一个 `source` 列，所以**加载时会把表头与旧行一起原地补齐**（旧行补 `complete`），否则只追加新行会让表头与数据行字段数不一致，pandas 全量读从此每次都在同一行失败。
- 窗口边缘截断的数据不会覆盖已保存的估算记录。
- **FlowMeter 的 CVD 从该合约、该粒度的可用买卖量估算累计**，包括部分覆盖和旧历史回填；真正缺失的 bar 留空。估算历史和已确认历史使用同一固定基准，后者优先且不重复累计，不随窗口滑动清零。每根 CVD 蜡烛使用自身 `cvdOpen` 和 `cvd` 绘制，前一根缺失也能显示。`cvdConfirmed` 独立提供仅包含核对通过记录的累计量。数据缺口前后不是连续成交全量，覆盖标记始终保留。
- TqSdk tick 窗口上限 10,000 条；按每 500ms 一条估算约 83 分钟，实际跨度受行情频率和休市影响。更早的买卖量依赖持续采集的历史文件；足迹不落盘，按需计算并在内存保留最多 800 根。
- tick 粒度持续采集落盘；其他粒度和足迹按请求启用计算，最后一次请求后保留约 60 秒。小周期 K 线在 SDK 线程按需订阅，每种最多 10,000 根。前端最多保留 800 根，tick 分类与聚合复用已完成 bar，只重算新增或修订部分；K 线口径聚合已订阅的小周期序列。

### 与 TradingView 的差异：30 秒粒度约 13% 的 bar 方向不一致

本项目的 K 线由 TqSdk **原样透传**，不做任何重采样或修正。所以与 TradingView 等其它数据源对比时，差异来自行情源本身，不是绘图。以下是 2026-09-11 夜盘用 `KQ.m@SHFE.fu` 对 TradingView `SHFE:FUX2026`（燃油 2611）30 秒周期逐根实测 45 根的结果：

- **开盘价 45/45 完全相同** —— 同一合约、同一 30 秒网格、同一时区，时间轴无误。
- **最高价恒 ≥ TradingView、最低价恒 ≤ TradingView**（分别 7 处、2 处不同，0 处更窄）—— TqSdk 的 bar 区间严格"包住"TradingView 的。
- **6/45 根（13%）阴阳方向相反**，这就是"K 线颜色对不上"的来源；且这 6 处**本项目的 close 全部等于 TradingView 下一根的开盘价**。
- 成交量逐根差 ±1~3%，方向不定。

后两条共同指向 **bar 右边界归属相差一个 500ms 快照**：TqSdk 的 bar 在右边界多含一个快照，于是它的 close 变成下一根的首笔价、区间把 TradingView 的整个包住。成交量互有高低，说明两路快照的采样时点本身也不同。旁证是 **TqSdk 自己的 tick 流与 K 线流也不逐 bar 相等**（同一窗口 170 根中只有 1 根完全相等，合计差 0.15%），可见这是快照行情的普遍特性，不是某一家数据商做错了。

已排除的可能：**主连拼接**（`KQ.m@SHFE.fu` 与具体合约 `SHFE.fu2611` 产出**完全相同**的 bar，且两者与 TradingView 的差异一致）、**周期**（对比方同为 30S）、**时区与时间轴**。

**30 秒粒度放大了这个现象**：该粒度下 |close − open| 常落在 0~2 跳以内，任何一路源的 1 跳差异就足以翻转阴阳。周期越短越明显。

**对指标的影响**：默认的 tick 判向（Lee-Ready）走 tick 流，不依赖 K 线 close，**不受此差异影响**，delta/CVD 不会被颜色翻转污染。反过来，「TV K线口径」按 `close > open` 归类，会把这约 13% 的方向噪声直接引进 delta 与 CVD —— **在 30 秒尺度上做方向判断，请用 tick 判向而非 K 线阴阳。**

同一数据目录请只运行一个服务进程，使用默认单 worker 启动方式。

## 数据备份

`data/` 里的买卖量历史无法从 TqSdk 重新生成，丢了就是丢了，所以服务在后台定期给它打快照（`backup.py`）：

- 每份快照是一个 `flowscope-data-YYYYmmdd-HHMMSS.zip`（先写临时文件再改名，不会留下半个包）。服务运行时**每 6 小时最多做一次**，启动时到期就补做；判断依据是上一份快照的时间，所以 `run.bat dev` 反复重载不会刷出一堆快照。
- 保留规则：最近 7 天的全部保留；更早的每个 ISO 周只留最新一份，最多 12 周。历史只追加，旧快照是新快照的子集，留着它们是为了"某次写坏了数据，过几天才发现"。备份目录里不是快照命名的文件一律不碰。
- 备份目录默认是项目下的 `backups/`（不入库）。与 `data/` 同盘只防误删和写坏，不防坏盘；可以在 `.env` 里设 `FLOWSCOPE_BACKUP_DIR` 指到别的盘或同步盘。
- 手动或用计划任务立即备份一次：`.\.venv\Scripts\python.exe backup.py [--dest 目录]`。
- **恢复**：停掉服务，把某个快照解压覆盖到 `data/`，再启动。
- 备份失败不影响采集，只在服务端打印 `[backup] 备份失败: ...`，并在 `/api/status` 的 `backup.error` 里显示，下一轮检查（10 分钟后）重试。

## 接口

- `GET /api/history?symbol=...&ltf=0&tf=30`：返回最近 800 根 bar 快照，包含 `source`（`tick` 或 `kline`）、`ltf`、`tf`、`revision`、`cvdBase` 和各 bar 的 `coverage`。`tf` 为主图周期秒数（10 或 30，非法值回落 30）；`ltf=0` 为 tick 口径，正数为 K 线口径的小周期秒数，非法或不能整除 `tf` 时回落为 0。返回的 `cfg.ltfOptions` 已是该周期下的合法子集。
- `GET /api/footprint?symbol=...&tf=30`：按需返回足迹快照，足迹跟随主图周期，包含 `revision`、`tickSize`（未知时为 null）和各 bar 的 `coverage`。
- `GET /api/status`：返回行情采集线程状态、最近错误和已订阅合约（形如 `KQ.m@SHFE.fu@30s`，同一合约的不同周期分别列出）。`collecting` 是常驻采集集合，`collectSkipped` 是超出名额、只在页面打开时才采集的部分；`backup` 是备份状态（`dir` 目录、`count` 份数、`latest` 最新一份、`error` 最近一次失败原因，正常为 `null`）。另有诊断字段：`jobQueue`（排队中的一次性查询数）、`busySec`（当前 SDK 调用已耗时，正常是 `null`）、`quietSec`（距上次收到行情流多久）、`lastProbeSec`/`probeError`（最近一次连接自检的间隔与失败原因）。
- `GET /api/favorites` / `POST /api/favorites?symbol=...` / `DELETE /api/favorites?symbol=...`：自选列表的读取、收藏（幂等，追加到末尾、不改变已有顺序）与移出，都返回 `{"symbols": [...], "max": 40}`。代码走与订阅相同的校验，非法代码或超过 40 个返回 400；收藏/移出不碰行情，所以是即时的，行情线程没连上也能改。
- `GET /api/watch?symbols=A,B,C&refresh=false`：自选面板用的轻量报价快照，每项含 `symbol`/`name`/`insClass`/`mainSymbol`/`lastPrice`/`basePrice`/`change`/`changePct`/`openInterest`/`volume`/`amount`/`priceDecs`/`expired`，取不到的字段是 `null`（NaN 不会是合法 JSON）。`openInterest`/`volume`/`amount` 都是**单边口径**的当日累计值，与菜单的「昨仓」同口径、可直接比较。只读报价对象、不订阅 K 线与 tick，1.5 秒 TTL 内多个页面的轮询只查一次；行情源不可用时返回 `source="unavailable"` 和空 `quotes`，不当作错误。
- `GET /api/symbol?symbol=KQ.m@SHFE.fu`：顶栏只读展示位用的合约名，返回 `{"symbol", "label"}`。主连先解析出当前标的月份合约再取中文名（`KQ.m@SHFE.fu` → 「燃油2611」，随主力换月变化），月份合约直接取自身名称；查询走合约服务的静态接口（不订阅行情），名字取不到时 `label` 回退成合约代码，所以展示位永远不会空着或报错。代码走与订阅相同的校验，非法返回 400。
- `GET /api/symbols?exchange=SHFE&product=fu&refresh=false`：合约选择器的数据源。不带参数时返回按交易所分组的全部主连品种（`exchangeId`/`exchangeName`/`productId`/`name`/`contSymbol`/`mainSymbol`/`openInterest`，组内按主力合约昨日持仓量降序）；带 `exchange`+`product` 时额外返回该品种的未下市月份合约（`symbol`/`name`/`openInterest`/`isMain`，同样按昨日持仓量降序）。`openInterest` 是交易所口径的**昨日持仓量**，只用于排序和下拉提示，不是实时值。`source` 为 `live` 或 `fallback`，`fallback` 表示行情源不可用（此时用内置常用品种、月份为空，`error`/`monthsError` 给出原因）；`refresh=true` 跳过缓存。查询全部是静态合约查询（不订阅行情）并在采集线程执行、带超时兜底，页面不会因为合约服务慢而卡住。
- `WS /ws?symbol=...&ltf=0&tf=30&footprint=false`：先注册订阅，再发送 `snapshot` 完整快照，随后发送带版本号的 `bars` 批量增量，包含最新 bar 和历史修订。`footprint=true` 还会接收 `footprints` 或 `footprint_snapshot`；两种数据分别跟踪版本号。所有消息都带 `symbol`/`tf`（`bars` 另带 `ltf`），前端据此过滤，不同周期不会互相串消息。
- 每次 WebSocket 重连都重新同步完整快照。慢客户端队列溢出时以 1013 关闭连接，前端自动重连补齐；15 秒无业务消息时发送包含行情源状态的 `ping`。

合约参数只接受字母、数字、点、下划线、短横线和 `@`，用于防止非法订阅与路径穿越。

## 订阅失败会自愈

订阅失败（合约代码打错、闭市或网络抖动导致 `get_quote` 一次性失败）**不是永久状态**，不需要重启服务：

- 失败后进入 **30 秒冷却期**。期间 `/api/history`、`/api/footprint` 与 `WS /ws` 会**立刻失败**并在 message 里写明「(N 秒后自动重试)」，不再让前端干等满 90 秒；`/api/status` 的 `failedFeeds` 也会列出原因。
- 冷却期一过，行情线程在后续循环**自动重订该合约，不需要页面开着**。失败登记保留到订阅真正成功后才清除；错误合约会继续冷却重试。
- 计算、历史写入和小周期订阅发生临时异常时，保留已成功的主订阅，**1 秒后重试处理**，不进入主订阅失败名单；重连也不会被这些错误阻止。
- 历史文件的格式问题**不再变成永久故障**：表头与数据行字段数不一致的旧文件在加载时原地补齐；个别坏行让 pandas 整表失败时退回逐行读取，能识别的行照常合并、坏行跳过（与增量读同一套规则），并在服务端打印一行 `[history] ... 解析失败(...), 退回逐行读取`。
- 冷启动时行情线程可能还没连上，目录会先回退到内置常用品种表（工具栏提示「目录: 离线常用品种」）。**行情连接被静默掐断**（长连接断开但没报错）是这一类长跑服务最常见的故障：tqsdk 不会抛异常，只会让之后**每个需要往返的调用各自卡满 30 秒**（`get_quote` 对没拿到合约信息的合约、`query_quotes` 都在等这个内部超时），表现就是「合约目录/月份查询超时」而图表还在用旧快照。现在有三道防线：① 查询耗时达到 30 秒上限即判定连接不可用，直接关闭重建；② 行情流安静超过 60 秒就主动做一次极短的合约查询探活，失败即重建；③ 查询卡住超过 20 秒时新请求立刻失败并回「行情连接无响应(N 秒)，正在重建」，不再让每个页面各等 12 秒。前端的目录失败会每 10 秒自动重试（最多 6 次），月份失败会在 8 秒冷却后于下次悬停/打开菜单时重试，都不需要刷新页面。
- 前端加载失败后**每 5 秒自动重试**（最多 24 次）。切换周期或数据源会取消旧请求、清除旧定时器并重置预算；迟到的旧响应和错误不会打断新视图的连接。
- 订阅池（`MAX_FEEDS=32`）按“合约＋主周期”计数：无在线客户端且**闲置满 600 秒**的健康或失败 Feed 会被回收（常驻采集的除外）。后台计算和自动重试不延长闲置期，断开最后一个客户端、或合约被移出常驻集合后重新计时。
- 回收曾访问过 SDK 的 Feed 时，采集线程会**关闭旧 TqApi 并重建仍需保留的订阅**（TqSdk 不能单独退订），释放 SDK 持有的行情缓存和连接资源。该过程会短暂重连；JSON 快照与历史缓存保留，恢复后同步更新。重新访问同一合约使用新 Feed 实例，不会被旧订阅标记跳过。为了少断几次，有一个已订阅的 Feed 到期时，**60 秒内也会到期的已订阅 Feed 一并回收**：连着取消几个自选、关几个页面只重连一次。没订阅过 SDK 的 Feed 回收时不重连，照常按各自的到期时间回收。

订阅冷却、处理重试、回收时长和回收合并窗口分别在 `ingest.py` 顶部的 `FAIL_RETRY_SEC`、`COMPUTE_RETRY_SEC`、`IDLE_EVICT_SEC`、`EVICT_BATCH_SEC` 里调整。
